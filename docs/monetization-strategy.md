## 0. 한 장 요약

**진단.** 이 사이트는 "돈이 되는 구조"가 아니라 **유입 자산**을 이미 갖고 있습니다 — 색인 대상 페이지 126개, 어휘 1,000개, 숙어 126개, 교재 72과(연습 576문항), 가이드 9편, LC/RC·S/W 훈련 문제, 그리고 숏폼 자동 생성·게시 도구(`promo/`). 반대로 **수익 인프라는 0** 입니다(계정 · 결제 · 광고 · 이메일 수집 없음). 분석은 이미 설치되어 있으나 학습 퍼널 이벤트는 아직 없습니다.

**결론 6줄.**

1. 광고 · 제휴만으로는 **월 10만원대**가 현실적 상한선입니다. 트래픽이 10배가 되어도 마찬가지입니다(§5). 교재 제휴 수수료는 건당 수백 원 수준입니다.
2. 큰 돈이 되는 지점은 **① 웹 밖 디지털 부가자료**와 **② B2B(학원 · 학교)** 입니다. 둘 다 **지금 구조(서버 없음 · 무료 코어)를 건드리지 않고** 만들 수 있습니다.
3. 더 큰 상한(**Pro 구독 · AI 첨삭 · MRR 수백만 원**)은 **계정 · 결제 · 서버**를 전제로 하며, 이는 GitHub Pages 정책상 **호스팅 이전이 선행**돼야 합니다(§4.4). 조건이 갖춰지기 전에는 착수하지 않습니다.
4. 가장 큰 병목은 수익 모델이 아니라 **유입과 측정**입니다. 지금은 방문자 · 전환 데이터가 없어 어떤 판단도 검증할 수 없습니다 → **Phase 0(측정)이 첫 작업**입니다.
5. 1인 운영이므로 판단 기준은 "월 매출"이 아니라 **시간당 수익**입니다(§5-5).
6. 세 문서가 서로 다른 전략을 폈는데, 이 문서는 **두 트랙을 병렬로 제시하되 현실 트랙(Track A)을 12개월 기본 계획으로 확정**하고 성장 트랙(Track B)은 진입 게이트를 통과할 때만 엽니다.

**권고(Track 채택).**

- **12개월 기본 = Track A** — 제휴 + 디지털 상품 + B2B + (조건부) 광고. 서버 · 계정 없이 즉시 착수. 기본 시나리오 **월 순이익 약 ₩454,000**(§5-3).
- **Track B는 조건부** — §4.4 의 세 게이트(측정 충족 · 재방문 신호 · 호스팅 이전 완료)를 모두 통과할 때 Phase 3에서만 착수. 통과 시 **월 MRR 수백만 원**(§5-4)까지 열리지만, 통과 전 투자는 금지합니다.

**12개월 목표(기본 · Track A).** MAU 10,000 · 월 순이익 ≈ ₩450,000 · 디지털 상품 누적 300건 · 학원 라이선스 1곳 · 시간당 수익 1만원 이상.
**Track B 착수 시 목표(조건부).** MAU 30,000 · MRR ≈ ₩6,500,000 · 유료 구독자 600명 · B2B 6곳.

**먼저 해야 할 3가지.** ① 4주간 기준선 측정(이벤트 설계 → §11) ② FAQ · 랜딩의 "모든 기능이 무료" 문구 정리(§6-5) ③ 상품 1종(전체 단어장 PDF + 발음 MP3) 제작과 판매 채널 개설(§3-2, Phase 2).

### 1-4. 시장 · 수요 구조

| 사실 | 수익화 함의 |
| --- | --- |
| 응시료 52,500원 · 연 26회 시행(2월 · 8월은 월 3회) | 시험 전 2~6주에 수요가 몰리는 **계절성**. 성수기에 상품 · 프로모션을 집중 |
| 응시자 1인당 연평균 응시 1.8회 · 63%가 연 1회 | **단명하는 고객**. 구독보다 **일회성 상품**이 맞고, 재방문은 시험 주기(3~6개월)로 설계 |
| 목표 점수대가 명확(700/800/900) | 상품을 **점수대별로 쪼갤 수 있음**(어휘 800+ / 900 도전 등) |
| 취업 · 승진 · 졸업 요건 등 **불가피 지출** | 지불 의사 자체는 있음. 문제는 **신뢰**(§1-5) |

**시장 규모(TAM/SAM/SOM, 추정)** — TAM(국내 영어 어학 학습 지출)은 수천억 원대, SAM(TOEIC 응시자 온라인 학습 지출)은 수백억 원대(추정). 우리의 현실적 상한(SOM)은 "1인 운영 + 기존 자산" 제약을 반영해 **연 2,000만~1.5억 원**(트랙에 따라, §5). 시장 전체를 노리는 전략은 리소스상 비합리적이며 **니치(어휘 + 첨삭) 집중**이 정답입니다.

### 2-2. 왜 2트랙인가 (통합의 핵심)

기존 3개 문서는 서로 다른 결론을 냈습니다. 하나는 "광고 · 제휴 상한 월 10만원, 디지털 상품 + B2B 중심"(서버 없음 유지), 다른 하나는 "Pro 구독 + AI 첨삭으로 연 7,800만원"(계정 · 결제 · 호스팅 이전 전제)이었습니다. 양쪽 모두 근거가 있으나 **전제와 시점이 다릅니다.** 이 문서는 둘을 한 문서에 담되, 전제가 다른 두 트랙으로 분리합니다.

| 축 | **Track A — 현실 트랙** | **Track B — 성장 트랙(조건부)** |
| --- | --- | --- |
| 전제 | 서버 · 계정 없음 유지(현 구조) | 계정 · 결제 · 서버 도입 + 호스팅 이전 |

| 상품 | PDF · MP3 · 모의고사 · 라이선스 · 제휴 | Pro 구독 · AI 첨삭 크레딧 |
| 수익 상한(12개월) | 월 수십만 원대 | 월 수백만 원대 |
| 착수 시점 | **즉시 (Phase 1~2)** | **Phase 3, §4.4 게이트 통과 시** |

**권고**: Track A를 12개월 기본 계획으로 확정하고, Track B는 게이트를 통과할 때만 엽니다. 이렇게 하면 ① 수익을 **즉시** 만들고 ② Track A의 실측 데이터가 Track B 착수 여부를 검증하며 ③ 서버 도입이라는 비가역 결정을 데이터로 미룹니다.

**Track B 진입 근거(요약)**: AI 첨삭은 스코어카드 최고점(27)이고, 라이팅 템플릿 콘텐츠를 그대로 자산화할 수 있습니다. 다만 **계정 · 결제 인프라가 선행**돼야 하므로 순서 의존성이 있습니다(§4.4).

### 3-2. 디지털 부가자료 (Track A 주력 · 매출의 절반)

**상품 철학**: 상품은 **스크립트 산출물**이다. 손으로 만든 파일은 자산이 아니라 유지비가 된다. 4단계를 한 번 묶어 두면 재생산 비용이 0에 가까워진다.

| 단계 | 도구(제안) | 입력 → 출력 |
| --- | --- | --- |
| 1. PDF 생성 | `tools/make_workbook.py` (신규) | `data/unitNN.js` → 유닛별 PDF 30종 + 전체 PDF |
| 2. 발음 MP3 | `edge-tts` — `promo/make_shorts.py`에서 이미 사용 중(무료 · 키 불필요) | 단어 · 예문 텍스트 → `mp3/01-037.mp3` |
| 3. 트랙 번호 매핑 | 위 스크립트에 포함 | (유닛, 단어) → `01-037` — PDF 본문과 MP3 파일명이 **같은 키**를 쓴다 |
| 4. QR 삽입 · 패키징 | QR 생성 + ZIP | 유닛 URL → QR 이미지, `PDF + mp3/` → 스토어 업로드용 ZIP |

**트랙 번호 규칙(고정)**: `유닛 2자리-단어 3자리` → `01-037`. PDF 표기와 MP3 파일명이 같은 값을 쓰므로, 한쪽만 바뀌면 어긋남을 잡도록 `npm run audit` 계열에 검사 항목을 추가한다(제안).

**용량 근거**: 단어 1개 발음(≈1초 · edge-tts 24kHz 모노)은 6~8KB라 **1,000단어 MP3 전체가 6~8MB**다. 예문까지 포함하면 30~50MB대. PDF에 심으면 모바일에서 버벅이므로 **오디오는 분리 보관**이 사실상 필수다.

**배포 형태 원칙 — 오디오를 PDF 파일 안에 심지 않는다.**

| 방식 | 재생되는 환경 | 판단 |
| --- | --- | --- |
| PDF 내장 오디오(Rich Media · Sound 주석) | 데스크톱 Acrobat만. 모바일 · Chrome · Edge · pdf.js · macOS 미리보기는 무시 | ❌ 미채택 |
| PDF 첨부 + 실행 액션 | 데스크톱은 경고 후 실행, 모바일 · 웹은 보안상 차단 | ❌ 미채택 |
| **QR → 사이트(브라우저 TTS)** | 기기 · OS 무관 | ✅ |
| **별도 MP3 ZIP + 트랙 번호** | 사용자 기기의 음악 앱 | ✅ |

PDF 내장 오디오는 PDF 표준이 아니라 **Adobe 확장**이라 데스크톱 Acrobat 밖에서는 재생되지 않는다. 오디오는 두 갈래로 제공한다.

- **온라인(QR)** — PDF 유닛마다 QR 1개 → 사이트의 브라우저 TTS로 즉시 재생. 배포 비용 0, 기기 무관. QR 링크에 `?utm_source=pdf` 를 붙여 PDF→사이트 유입을 측정(QR이 촘촘해지지 않게 파라미터는 짧게, QR은 크게).
- **오프라인(MP3 ZIP)** — PDF 본문에는 트랙 번호(`▶ 01-037`)만 인쇄하고 음원은 별도 동봉.

> **QR 대상 페이지 — 선행 작업 필요**: 현재 브라우저 TTS 듣기 버튼(`.gex-speak` · `assets/speak.js`)을 가진 곳은 어휘 빈출 200선(`units/frequency.html`), 혼동 어휘(`units/confusion.html`), 문법 교재, 회화 교재 페이지다. **유닛 30개 페이지(`units/unit-NN.html`)에는 아직 듣기 버튼이 없다.** 따라서 1차 QR은 듣기 버튼이 있는 페이지나 홈 앱(`/`)을 가리키고, 유닛별 QR을 쓰려면 유닛 페이지에 듣기 버튼을 먼저 붙인다(`tools/build-pages.mjs` 작업).

**결제 · 배포 경로 — 사이트는 퍼널, 판매는 스마트스토어**

판매 채널을 고르는 문제가 아니라 **유입(사이트)과 결제(외부 채널)를 분리**하는 문제다.

```
toeic.monster  →  유입 · 신뢰 · 상품 소개 (무료 학습 + 상품 소개 페이지 1개)
                 ↓  UTM(utm_source=store)
스마트스토어    →  결제 · 자동 다운로드 · 환불 CS
```

| 방안 | 장점 | 단점 |
| --- | --- | --- |
| **스마트스토어**(권장) | 결제 · 자동 다운로드 · 환불 CS 내장, 결제 신뢰도, **네이버 검색 · 쇼핑 노출 = 획득 채널** | **사업자등록 필요**(전자출판업 58221 등), 수수료 4~6%, 구매자 데이터 미보유 |
| 자체 결제(토스페이먼츠 등) | 마진 높음, 브랜드 통일, 번들 · 가격 실험 자유 | 사업자등록 + PG 심사 + 다운로드 링크 보호 구현, **호스팅 이전 선행**(§4.4) |
| 외부 마켓(크몽 · 탈잉) | **사업자등록 없이 시작 가능**(플랫폼 원천징수), 즉시 판매 | 수수료 높음, 브랜드 종속 |

**스마트스토어를 먼저 고른 근거** — 이 사이트의 제약에서 나온 결론이다.

1. **서버 없음** — 정적 GitHub Pages라 결제 · 웹훅 · 다운로드 링크 보호를 직접 못 붙인다. 셋 다 스토어에 내장.
2. **신뢰 부족** — 유입은 검색 콜드 트래픽이고 브랜드 인지도가 낮다. 낯선 개인 도메인 결제 화면보다 스토어 결제 화면의 전환율이 높다.
3. **유입이 곧 수익** — 구매자는 네이버 검색 · 쇼핑 안에 있다. 스토어는 결제 수단이면서 동시에 **획득 채널**이다.
4. **CS 위임** — 청약철회 · 분쟁 대응을 플랫폼이 처리한다. 1인 운영에서 CS 시간은 곧 비용.
5. **속도** — 개설 1주 vs 자체 결제(등록 + PG 심사 + 구현) 수 개월.

**자체 결제로 이전하는 조건** — 수수료 차이는 매출의 4~6%뿐이라, 매출이 작을 때는 개발 · 유지비가 그 차액을 훨씬 넘는다. 아래 중 하나일 때만 옮긴다: ① 상품 월 매출 100만원 이상(수수료 4~6만원 ≈ 자체 결제 유지비) ② 번들 · 업셀 · 가격 A/B를 상시로 돌려야 함 ③ 구독 · 기기 간 동기화를 상품에 묶어야 함(→ Track B).

> **사업자등록**: 반복 · 계속 판매는 채널과 무관하게 등록 대상이다(§9). 등록 전 가설만 빠르게 검증하려면 크몽이 유일한 우회로다.

### 3-3. B2B 라이선스 (학원 · 학교 · 교사)

단가가 가장 높고(연 단위), 무료 코어를 건드리지 않으며, **Track B의 인프라 없이도 시작 가능**한 유일한 고단가 상품이다.

| 항목 | 내용(제안) |
| --- | --- |
| 과금 단위 | 학생 좌석 수(100석 단위) 또는 학원 단위 |
| 가격 | 학원당 월 50,000원 ~ 연 500,000원(원생 100명 기준 인당 500원) |
| 제공 | 반별 단어 배정, 진도 · 오답 리포트(수동 요약 → 이후 자동화), 교재 패키지 |
| 파일럿 조건 | 1개월 무료 → 유료 전환 |
| 목표 | 12개월 내 1~2곳 |

**왜 학원이 돈을 내는가**: 학원의 실제 고통은 "학생이 숙제를 했는지 확인하는 일"이다. 이는 개인 학습 앱이 해결하지 않는 영역이다. Track A에서는 리포트를 **수동 · 반자동**으로 제공하더라도 가치가 성립한다(자동 대시보드는 Track B).

**아웃리치**: 학원 · 교사 대상 무료 라이선스 제안 메일, 시범 도입 1곳 확보(§13 12주차).

### 3-4. 광고 (조건부 · 마지막)

광고는 **학습 UX를 해칠 위험**이 있어 Track A에서도 조건부로만 검토한다(Section 1개 원칙). 채택 시에는 **무료 사용자 한정** 지면, 콘텐츠와 섞이지 않는 위치, 로딩 영향 0에 가까운 포맷을 쓴다. 광고 지면 추가 주에는 **학습 지표가 떨어지지 않았는지**를 항상 함께 본다(§11-4). RPM 가정은 §5-1.

### 3-5. 후원 (보조)

건당 3,000원 수준의 보조 수단. **주 수익원으로 기대하지 않는다**(전환율이 구조적으로 낮음). 문의 창구와 함께 최소한으로 연다.

### 4-4. Track B 진입 게이트 (모두 충족해야 착수)

| # | 게이트 | 통과 기준 | 통과 전 금지 사유 |

**호스팅 이전 판단**: GitHub Pages 정책은 "온라인 사업 · 전자상거래 · 상업적 SaaS 목적의 무료 호스팅" 용도를 허용하지 않는다(§15). 해석 여지가 있지만 **자체 결제 · 구독을 사이트 안에 붙이는 순간** 위험이 실질화된다. 광고 · 제휴 수준은 유지 검토(위험 낮음). 도구 대부분이 `_site/` 구성 후 그대로 배포 가능하므로 이전 비용은 낮다.

**계정 · 동기화 조합(조사 결과 후보)**: 인증은 Clerk 류, DB는 Neon(Postgres) 류, 실행은 서버리스 함수(Cloudflare Pages Functions · Vercel). 셋 다 무료 티어로 시작 가능하지만 **우리 스택은 프레임워크가 없으므로** 소규모 서버리스 함수만 따로 두는 방식이 유지비가 가장 낮다. 결제는 국내 사용자 비중이 절대적이고 간편결제 의존도가 높으면 **국내 PG 병행**을 Phase 1 착수 전에 결정한다. 실제 선택은 진입 시점에 다시 조사한다(요금 · 정책 변동).

### 4-5. Track B 구현 시 주의사항

1. **구독 상태는 반드시 웹훅으로 동기화** — 클라이언트 응답을 신뢰하지 않는다.
2. **결제 키는 서버사이드에서만 사용** — 클라이언트 노출 금지.
3. **찜삭 API는 서버 경유** — API 키 보호 + 사용량 제어.
4. **크레딧 차감은 트랜잭션으로** — 중복 차감 / 미차감 방지.
5. **AI 결과 고지** — 자동 채점임을 명시, "예상 점수"로 표현(점수 보증 금지).

### 5-3. Track A 시나리오별 월 수익 (추정)

| 모델 | 보수(3,000) | 기본(10,000) | 낙관(30,000) |
| --- | --- | --- | --- |
| 광고 | 24,000 | 80,000 | 240,000 |
| 제휴 | 9,000 | 30,000 | 90,000 |
| **디지털 상품** | 89,100 | **297,000** | **891,000** |
| B2B | 0 | 50,000 | 250,000 |
| 후원 | 9,000 | 20,000 | 60,000 |
| **합계** | **131,100** | **477,000** | **1,531,000** |
| 채널 수수료(약 6%) | -5,900 | -19,600 | -58,900 |
| 도메인 · 도구(월) | -3,000 | -3,000 | -10,000 |
| **세전 순이익** | 약 **₩122,000** | 약 **₩454,000** | 약 **₩1,462,000** |

**읽는 법 3가지**

1. 광고 + 제휴(1 · 2번)를 합쳐도 기본 시나리오에서 **월 11만원**입니다. 트래픽을 10배로 만들어도 50만원대 — **광고는 주 수익원이 될 수 없습니다.**
2. 매출의 **약 62%**(기본)가 디지털 상품 한 줄에서 나옵니다. 우선순위가 여기여야 하는 이유입니다.
3. B2B는 학원 1곳만으로 기본 시나리오 매출의 10%를 만듭니다. **단가가 가장 높은 채널**입니다.

> 이전 문서들은 전환율 · 요율을 다르게 잡아 합계가 달랐습니다(예: 디지털 상품 낙관 시나리오를 0.5% 전환으로 계산해 1,485,000원). 이 문서는 **A4~A7 가정을 고정**해 재계산했고, 가정이 바뀌면 위 표만 교체합니다.

### 5-4. Track B 시나리오 (조건부 · 참고)

Track B를 게이트 통과 후 착수했을 때의 목표치입니다(추정). 전환율 · 이탈률 가정이 Track A보다 훨씬 민감합니다.

| 지표 | 3개월 | 6개월 | 12개월 |
| --- | --- | --- | --- |
| 월 반복 매출(MRR) | 450,000 | 1,950,000 | 6,500,000 |
| 유료 구독자 | 80명 | 250명 | 600명 |
| B2B 계약 학원 | 0곳 | 2곳 | 6곳 |
| 월 순이익(추정) | -100,000 | 1,100,000 | 4,300,000 |
| 연 환산(run-rate) | — | — | **약 78,000,000** |

비용 구조(월, 기본 후반): 서버 150,000 · LLM · STT 원가 매출의 3~5% · 결제 수수료 3.5% · 콘텐츠 · 디자인 외주 1,000,000 · 도구 100,000. **인건비는 계상하지 않음**(1인 운영의 기회비용은 별도 관리).

**Pro 구독 단위경제성**: 평균 유지 기간 = 1 ÷ 월이탈률 10% = 10개월. LTV(총) = 4,900 × 10 = 49,000원, LTV(순, 마진 85%) ≈ **41,650원**. **BEP 구독자 수 = 고정비 60,000 ÷ (4,900 × 0.85) ≈ 15명.** 즉 Track B의 첫 마일스톤은 "유료 15명"입니다.

**찜삭 건당 원가**: 판매가 1,500원 → LLM 추론 25원 · 결제 수수료 53원 → **공헌이익 1,422원(94.8%)**. 경보 기준: 원가가 판매가의 20%(=300원) 초과 시 가격 또는 모델 정책 재검토.

### 5-7. 방문자 수(MAU) 단계별 전략 플랜

### 6-3. 상품이 노출될 위치 (전환율 순)

1. 시험 모드 결과 화면(예상 점수 직후) — 감정 최고점
2. 학습 완료 화면("이 유닛을 종이로") — 오답노트 인쇄물
3. 교재 페이지 하단(72개) — "이 과의 문제를 PDF로"
4. 점수별 로드맵 섹션
5. FAQ · 홈 하단 — 전체 상품 안내

### 6-4. 업셀 경로 (무료 → 유료)

```
무료 학습 → 시험모드 결과 → 오답노트 PDF → 전체 단어장(9,900) → 번들(12,900) → (Track B) Pro → AI 찜삭
```

각 단계는 **다음 단계의 필요를 직전 단계에서 만들도록** 설계한다(예: 시험 결과 화면에서 오답이 많으면 상품 노출).

### 6-5. 문구 정리 (선행 작업)

현재 홈 · FAQ 는 "웹에서 제공하는 학습 기능은 모두 무료" 라고 적혀 있고, 유료 부가자료 가능성도 한 문장 언급되어 있습니다. 상품 출시 시점에는 **"웹 학습 기능은 모두 무료, 인쇄 · 오디오 등 웹 밖 자료는 유료"**(Track B 착수 시 "개인화 기능 포함") 로 명시해야 합니다. 어긋나면 신뢰 문제가 되고, 환불 분쟁의 근거가 됩니다.

| **4. 확장** | 12~24개월 | A/B | 규모 · 영역 확장 | 관리자 대시보드 · PWA · 스피킹/오픽 · 라이선스 3곳 | 월 순이익 100만원 이상 | 유지비 > 매출 증가분 → 동결 |

**각 Phase 착수 전 공통 확인**: `npm run audit` · `npm audit`(외부 의존성 0 유지) · 학습 지표가 악화되지 않았는지(§11-4).
