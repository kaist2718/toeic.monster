# `index.html` 프리렌더 마크업 경량화 검토 (실행 전 계획)

> 작성: 2026-09-18 · 상태: **검토 완료 · 실행 전** · 관련 기록: `docs/app-split-plan.md`(스타일·스크립트·데이터 분리) · `docs/ux-review.md` §20

## 0. 왜 이 문서가 필요한가

`docs/app-split-plan.md` 1·2단계로 `index.html` 은 628KB → 283.5KB 가 되었습니다.
스타일(`assets/app.css`)·스크립트(`assets/app.js`)·데이터(`data/app-data.js`)를 모두 파일로 뺀 뒤에도
남은 283.5KB 가운데 **67%가 프리렌더 마크업**입니다. "그럼 이것도 파일로 빼면 되지 않나?" 가
자연스러운 다음 질문인데, **그 답은 "아니오"에 가깝습니다** — 그 이유와 대안을 정리합니다.

## 1. 실측 (2026-09-18)

## 2. "파일로 빼면 안 되는" 이유 (핵심)

프리렌더의 **목적 자체가 그 내용을 `index.html` 안에 두는 것**입니다(`tools/prerender-home.mjs` 도입 이유):

- 자바스크립트를 실행하지 않는 크롤러(네이버 Yeti 등)가 읽어야 합니다.
- 자바스크립트를 끈 사용자도 내용을 읽을 수 있어야 합니다.

그래서 프리렌더 내용을 `data/*.js` 처럼 **외부 파일로 옮기면 목적이 사라집니다** — 첫 화면에
JS 로 채워 넣어야 하고, 그 순간 두 조건이 모두 깨집니다. 즉 선택지는 "옮기기"가 아니라
**"줄이기" 또는 "별도 정적 페이지로 나누기"** 뿐입니다.

## 4. 권고안 — 1단계: `freqGrid` → `units/frequency.html`

가장 큰 한 덩어리(54.4KB, 200개 목록)만 별도 정적 페이지로 옮깁니다.
`units/`·`guides/` 가 이미 같은 방식(생성기 `build-pages.mjs`)으로 만들어져 있어 새 구조가 필요 없습니다.

1. `build-pages.mjs` 에 **빈도순 기출 어휘 페이지**(`units/frequency.html`)를 추가합니다.
   - 데이터 출처는 `data/app-data.js` 의 빈도 데이터(현재 프리렌더가 쓰는 것과 같은 값).
   - 단어장 허브(`units/index.html`)와 홈 `freqGrid` 섹션에서 링크합니다.
   - `sitemap.xml` 에 자동 포함(생성기가 이미 처리), `sw.js` 프리캐시 허브 목록에 `units/` 계열로 포함.
2. `index.html` 의 `freqGrid` 프리렌더는 **상위 20개 + 「전체 200개 보기」 링크**로 줄입니다.
   - 앱이 로드되면 지금처럼 전체 200개를 그립니다(화면 동작은 그대로, 미리 심은 양만 줄임).
3. 감사·문서 수치를 함께 갱신합니다(`audit-site` 의 색인 페이지 수, `docs/ux-review.md` 의 실측표).

**예상 효과**: `index.html` 283.5KB → 약 240KB(프리렌더 −40KB 내외) · 색인 페이지 124 → 125개.

## 5. 2단계(선택) — `confuseGrid`·`mnemonicGrid` 검토

1단계를 하고 나면 `confuseGrid`(20.0KB)·`mnemonicGrid`(12.6KB)가 다음 후보입니다.
다만 이 둘은 "목록"보다 **학습 카드** 성격이라 홈에 있는 편이 학습 흐름에 맞습니다.
1단계 결과를 보고, 필요하면 같은 방식으로 판단합니다.

## 6. 검증 방법

```bash
npm run build          # 생성기 + 프리렌더 (결과물 커밋 대상)
npm run verify         # 생성물이 HEAD 와 어긋나지 않는지 (프리렌더 --check 포함)
npm run audit          # 링크·자산·사이트맵·문서 수치 (색인 페이지 수 변화 반영)
npm run check:browser  # 홈 섹션·이동·딥링크가 그대로인지 (100여 항목)
npm run check:staged   # 배포본에서도 같은지
npm run perf:compare   # 첫 방문 총량이 늘지 않았는지
npm run audit:external # 배포 후 색인·링크 상태
```

색인 관점 확인: 새 페이지가 `sitemap.xml` 에 있고, 홈에서 내부 링크로 닿는지(`audit-site` 3-1).

## 7. 하지 않을 것

- 프리렌더 내용을 JS 로 채우기(§2).
- 홈의 앱 구조·딥링크·화면 전환을 건드리기(1단계는 생성물 추가 + 프리렌더 분량 축소뿐).
- 콘텐츠 항목 수 줄이기(검색·학습 가치 손실).
