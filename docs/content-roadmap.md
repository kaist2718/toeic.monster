## 2. 감사 체계 (Audit Gates)

| 명령 | 보는 것 |
| --- | --- |
| `npm run audit:content` | 어휘·숙어·확장 콘텐츠의 중복·형식, “정답이 보기에 없는 문항”, 교차 중복, 총량 표기 일치 |
| `npm run audit:text` | 화면에 보이는 모든 문자열의 맞춤법·영문 철자·공백·전각 문자·TTS 낭독 기호 |
| `npm run audit:site` | **내부 링크·앵커, 정적 자산, HTML 중복 id, 메타·JSON-LD, 사이트맵 일치, 문서 수치, 홈 고정 표시값, 본문 서체 서브셋(5-3)** |
| `npm run audit:a11y` | **접근성·성능 예산** — lang·제목 단계, 입력 요소 이름, ARIA 참조, 초점 표시, 색 대비(WCAG), 파일 크기 상한·head 동기 스크립트 |
| `npm run audit:external` | 위 항목 + 외부 링크 HTTP 상태 (네트워크 필요) |
| `npm run test` | TTS 음성 선택 로직 + 문법 문제 풀이 연동 회귀 테스트 |
| `npm run check` | 감사 3종 + 테스트 + 빌드 (커밋 전 권장) |
| `npm run check:ci` | `check` + 생성물 커밋 누락 감지(`verify`) |

### 2-1. 이번에 메운 사각지대

기존 감사는 “콘텐츠 내용”만 보고 “사이트 구조”는 보지 못했습니다. `tools/audit-site.mjs` 를 추가해 아래를 자동 점검합니다.

| 점검 항목 | 왜 필요한가 |
| --- | --- |
| 내부 링크·앵커 | `guides/*` 카드 링크, 섹션 앵커(`#today-section`)가 깨지면 이동이 실패한다 |
| 정적 자산 | 아이콘·매니페스트·데이터 스크립트 경로 오타는 런타임에야 드러난다 |
| 중복 id | `document.getElementById` 가 엉뚱한 요소를 잡는다 |
| 메타·OG·canonical | 검색·공유 미리보기 품질. canonical 과 og:url 불일치는 중복 색인을 만든다 |
| JSON-LD 형식 | 구조화 데이터가 JSON 파싱에 실패하면 리치 결과가 사라진다 |
| 사이트맵 ↔ 페이지 | **noindex 페이지를 사이트맵에 제출하면 서치콘솔이 오류로 보고한다** |
| 문서 수치 | 문서와 실제 데이터가 어긋나면 우선순위 판단을 그르친다 |
| 홈 고정 표시값 | 자바스크립트가 채우기 전 첫 화면·`<noscript>` 목차에 틀린 숫자가 보인다(`표현 0개`, 배지 `0 / 0 획득`) |

### 2-2. 게이트가 즉시 찾아낸 실제 오류

- `privacy.html`·`terms.html` 이 `robots=noindex` 인데도 `sitemap.xml` 에 포함되어 있었습니다.
  → `tools/build-pages.mjs` 에서 두 URL 을 사이트맵 생성 대상에서 제외했습니다.
- `docs/search-indexing.md` 의 “사이트맵 35개 URL”, “숙어 60선”, `docs/monetization-plan.md` 의 “약 6,500줄” 등 오래된 수치를 제거하고 `audit:counts` 블록으로 대체했습니다.

> 문서에 수치를 적을 때는 `<!-- audit:counts ... -->` 블록을 쓰세요. 본문에 직접 적으면 드리프트가 다시 쌓입니다.

## 5. 타 시험 확장 검토 (기획 결론)

### 5-1. 전제 진단 — 현재 코드는 “TOEIC 단일 시험” 하드코딩

| 하드코딩 지점 | 내용 |
| --- | --- |
| 전역 변수 | `VOCAB_UNITS` / `VOCAB_IDIOMS` / `TOEIC_EXTRA` |
| 빌드 스크립트 | `for (i = 1..30)`, `SITE = "https://toeic.monster"`, 제목 문자열 “TOEIC 필수 어휘 1,000”, 출력 경로 `units/` 고정 |
| 감사 도구 | 동일한 파일 목록·변수명 가정 |
| `index.html` | UI·렌더러·콘텐츠가 한 파일에 혼재 |

→ 시험별 복제 방식은 유지비가 시험 수에 비례해 늘어납니다.
**“시험 레지스트리 + 공용 엔진” 리팩터링(기능 변화 0인 순수 구조 작업, 1~2주)** 이 모든 확장의 선행 조건입니다.

### 5-2. 후보 평가

| 시험 | 사용자 겹침 | 콘텐츠 재사용 | 브랜드 적합 | 판단 |
| --- | --- | --- | --- | --- |
| **TOEIC Speaking·Writing** | 매우 높음 | 매우 높음 | 일치 | 확장이 아니라 **완성** — 이번에 완료 |
| TOEIC Bridge | 낮은 레벨·별도 수요 | 높음 | 일치 | 서브패스 `/bridge/` 후보 (수요 검증 후) |
| OPIC | 스피킹 사용자 겹침 큼 | 낮음 (평가·등급 체계 상이) | 불일치 | 신규 도메인 필요 |
| TEPS | 일부 | 낮음 | 불일치 | 수요 감소 → 후순위 |
| TOEFL / IELTS | 낮음 (학술 어휘로 성격 반대) | 매우 낮음 | 불일치 | 비권장 |
| G-TELP · 수능·공무원 영어 | 낮음 | 낮음 | 불일치 | 비권장 |

브랜드 자산(`toeic.monster`)이 재사용되지 않으므로 타 시험은 사실상 **신규 프로젝트**입니다(서버·계정·결제가 없다는 점만 유리).

### 5-3. 권고 3단계

1. **완성 단계 (완료)** — Speaking·Writing을 실제 문항 구성까지 맞춰 4기능 콘텐츠를 닫습니다.
2. **검증 단계 (다음)** — 서치콘솔의 노출·클릭 데이터로 확장 여부를 판정합니다. 도메인을 유지할 수 있는 **TOEIC Bridge** 만 서브패스 후보로 남깁니다.
3. **분리 단계 (조건 충족 시)** — 시험 레지스트리 리팩터링 + 새 도메인 준비 후 OPIC 등을 **별도 프로젝트**로 진행합니다.

### 5-4. 착수 조건 (트리거)

- TOEIC S&W 커버리지 ≥ 70% → **달성**
- 홈 상위 키워드 3개 이상 안정 노출 → 서치콘솔 데이터로 확인 필요
- 두 조건이 모두 충족되면 2단계(TOEIC Bridge) 검토를 시작합니다.

## 8. 실행 명령

```bash
npm run audit          # 콘텐츠 + 문구 + 사이트 구조 감사
npm run audit:external # 외부 링크 HTTP 상태까지 확인 (네트워크 필요)
npm run check          # 커밋 전 기본 점검 (감사 3종 + 테스트 + 빌드)
npm run check:ci       # 생성물 커밋 누락까지 감지
```

> 콘텐츠(`data/*.js`, `index.html` 배열)를 수정한 뒤에는 `npm run build` 로
> `units/`·`guides/`·`sitemap.xml` 을 재생성하고 함께 커밋해야 합니다.
> `npm run check:ci` 가 이 누락을 잡아냅니다.

## 9. CI (GitHub Actions)

`.github/workflows/ci.yml` 이 위 게이트를 자동 실행합니다. 외부 의존성이 0개라 **설치 단계 없이** 바로 검사합니다.

| 워크플로 작업 | 실행 시점 | 동작 |
| --- | --- | --- |
| `check (Node 18.x · 20.x)` | push(main) · pull_request · 수동 | `npm run check:ci` — 감사 3종 + TTS 테스트 + 빌드 + 생성물 커밋 누락 감지. **실패하면 머지 불가** |
| `external-links` | 주 1회 예약 · 수동 | `npm run audit:external` — 공식 ETS 안내 등 외부 링크 HTTP 상태. 상대 사이트 사정으로 끊길 수 있어 `continue-on-error` 로 알림만 하고 CI를 막지 않습니다 |

- Node 18·20 두 버전에서 도는 이유: `package.json` 의 `engines(>=18)` 을 실제로 지키는지 확인하기 위해서입니다.
- `check` 가 실패하면 로그의 `npm run verify` 출력에서 **어느 생성 파일이 달라졌는지** 바로 볼 수 있습니다.
  그대로 `git add` 후 다시 커밋하면 됩니다.
- 같은 브랜치에 연속 푸시하면 앞선 실행은 자동 취소됩니다(`concurrency`).

### 9-1. `verify` 를 교체한 이유 (중요)

기존 `verify` 는 `git diff --exit-code -- units guides sitemap.xml` 이었습니다. 그런데 `sitemap.xml` 의 `<lastmod>` 는
**`data`·`index.html` 을 마지막으로 건드린 커밋 날짜**에서 나옵니다(`tools/build-pages.mjs` 의 `lastModified()`).

```
① 빌드 실행  →  lastmod = “마지막 커밋 날짜” (예: 09-12)
② 커밋 생성  →  이제 “마지막 커밋 날짜”가 09-13 으로 바뀜
③ 빌드 재실행 →  lastmod = 09-13  →  커밋된 파일(09-12)과 달라짐
④ verify 실패 — 내용은 완전히 같은데도 실패
```

빌드 결과 자체는 결정적(재실행해도 동일)이지만, **커밋이라는 사건이 입력을 바꾸기 때문에**
이 비교는 커밋 직후·CI 에서 항상 실패합니다. 그래서 `<lastmod>` 만 비교에서 빼고
`tools/verify-generated.mjs` 로 검증하도록 바꿨습니다. 실제로 잡아야 할 것은
“생성물을 커밋하지 않은 경우”이지 “날짜가 하루 달라진 경우”가 아니기 때문입니다.
