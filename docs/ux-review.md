## 2. P2 — 불편·일관성 문제 (모두 수정)

### 2-1. 홈 한 페이지에 52개 섹션을 한 줄 칩 49개로 탐색 ✅

- **증상**: `.section-nav` 가 `overflow-x: auto` 라, 가로 스크롤이 있다는 단서 없이 49개 칩을 옆으로 밀어야 했습니다. 데스크톱(마우스)에서는 뒤쪽 칩 접근이 특히 어려웠습니다.
- **조치**: ① 자주 쓰는 8개만 위 줄에 노출 ② 나머지 44개는 `🗂 전체 목차` 버튼으로 **주제별 4묶음**(어휘 익히기 / 파트별 훈련 / 말하기·쓰기 / 실전·학습 관리)에 담아 접기 ③ 넓은 화면(≥900px)은 펼친 상태로 시작 ④ `aria-expanded`·`aria-controls` 로 접힘 상태 노출.
- **검증**: 섹션 52 = 칩 52(모두 연결) · 그룹 4개 · 토글 동작 · `npm run audit` 의 "섹션 메뉴 칩 52개(모두 연결됨)".

### 2-2. 정적 페이지에서 앱 학습으로 돌아오는 길이 없음 ✅

- **증상**: 교재 페이지 CTA 가 `홈` 하나뿐이고 앱은 해시를 해석하지 않아, "이 교재의 문제를 앱에서 풀기" 로 바로 연결할 수 없었습니다.
- **조치**: ① 앱에 해시 진입 지원(`goToHash` — `#grammar-quiz`·`#grammar-quiz-basic` … `#units`·`#dashboard` 등) ② `?level=basic#grammar-quiz` 형태로 **단계까지 지정해 바로 시작** ③ 교재 상단에 `✏️ 이 교재 문제 풀기` 버튼 배치.
- **검증**: 교재 → 앱 링크 계측(`../index.html?level=basic#grammar-quiz`), `applyLevelQuery()` + `hashchange` 리스너 확인.

### 2-3. 같은 화면에 이름이 비슷한 문법 진입점 3개 ✅

- **증상**: `📘 문법 가이드`(자료 허브의 탭) · `📘 문법 교재`(칩) · `✏️ 문법 문제`(칩)가 한 화면에 공존해 무엇이 다른지 구분되지 않았습니다.
- **조치**: 첫 번째를 목적지 이름인 **`📐 필수 문법 보기`** 로 변경.

### 2-4. 모바일 터치 영역이 44px 미만인 컨트롤 ✅

- **증상**: `.btn` 이 모바일에서 약 33px, `quiz-head select` 가 38px 이었습니다.
- **조치**: `select` → `min-height: 44px`, 모바일 `.btn` → `min-height: 40px`(프로젝트가 쓰던 "약 40px" 기준에 맞춤).
- **검증**: `@media (max-width: 640px)` 규칙 계측.

### 2-5. 문법 표가 좁은 화면에서 빽빽함 ✅

- **증상**: `.gtable` 3열이 375px 화면에서 한 열 약 100px 로 좁아 읽기 어려웠습니다.
- **조치**: 표를 `.gtable-wrap`(`overflow-x: auto`) 로 감싸고 `min-width: 340px` 를 주어, 좁은 화면에서는 표만 가로로 밀리게 했습니다. 520px 이하에서는 글자·여백을 한 단계 줄였습니다.

### 2-6. 많은 조작 요소에 키보드 초점 표시가 없음 ✅

- **증상**: `:focus-visible` 규칙이 `.btn`·`.lvl-btn`·`.quiz-opt` 등 6종에만 걸려 있어, **섹션 칩·토글·오답 보기(`.bank-opt`)·모드 버튼(`.mode-btn`)·유닛 버튼** 등은 키보드로 이동해도 어디에 초점이 있는지 보이지 않았습니다.
- **조치**: `a` · `button` · `summary` · `select` · `input` · `[tabindex]` 전역 `:focus-visible` 윤곽선(3px `--accent`)으로 통일.
- **검증**: 계측 — 접근 가능한 이름이 없는 버튼 0개, 라벨 없는 `select`/`input` 0개, 중복 `id` 0개.

### 2-7. 상단 칩 순서가 문서 순서와 어긋남 ✅

- **증상**: 첫 줄 칩이 `… 문법 문제(6번째 섹션) → 오늘의 대화문(23번째) → 학습 모드(7번째)` 순이어서, 대화문으로 갔다가 다시 위로 되돌아와야 했습니다.
- **조치**: `학습 모드 → 오늘의 대화문` 순으로 교체해 첫 줄이 `1·2·3·4·5·6·7·23` 로 단조 증가하게 했습니다.

## 4. 메인 페이지(`index.html`) 집중 점검

진입 → 탐색 → 학습 → 복습 4단계로 나눠 실제 조작 순서를 따라가며 확인했습니다.

### 4-1. 진입 (첫 화면)

| 확인 항목 | 결과 |
| --- | --- |
| 건너뛰기 링크 | ✅ `<a class="skip-link" href="#mainContent">본문으로 바로가기</a>` — 키보드 사용자가 상단바를 건너뛰고 본문으로 바로 이동 |
| 문서 구조 | ✅ `<html lang="ko">`, `h1` 1개(사이트명), 이후 섹션 제목은 `h2` 58개 — 제목 단계가 어긋나지 않음 |
| 첫 화면 정보 위계 | ✅ 배지 → 제목 → 부제 → 오늘의 응원 문구 → 누적 지표 4개 → 주요 CTA 3개(`오늘의 퀴즈`/`암기 카드`/`실력 진단`) 순으로 시선이 자연스럽게 내려감 |

## 5. 잘 되어 있는 점 (유지)

- 문항 카드·보기·피드백이 모두 `<button>` 기반이라 키보드만으로 풀이가 가능합니다.
- 영어 단어·발음기호·예문에 `lang="en"` 이 적용되어 화면 낭독기가 영어로 읽습니다(앱 렌더러 + 정적 페이지 공통).
- 정적 페이지의 🔊 버튼은 앱의 TTS 설정(`toeic1000_ttsvoice`·`ttslang`·`ttsrate`)을 공유해 목소리·속도 선택이 페이지를 넘어 이어집니다.
- 미지원 브라우저에서는 🔊 버튼을 숨기고(`hidden`), Esc 로 낭독을 멈출 수 있습니다.
- 새 문법 섹션은 정적 링크(`바로가기`)를 함께 노출해 JS 를 실행하지 않는 크롤러(네이버 Yeti)도 교재 3권을 발견할 수 있습니다.
- 오답노트를 포함한 모든 학습 기록은 localStorage 에만 저장되고 서버로 전송되지 않습니다.

### 7-2. 첫 화면에서 숨은 목록 1,000장을 만들고 있었음 ✅

| **캐시 주의** | 인라인일 때는 HTML 과 함께 항상 새 스타일이 왔지만, 파일로 빼면 브라우저·서비스워커 캐시를 거칩니다. 그래서 서비스워커가 설치 때 두 파일을 함께 담고, 배포할 때마다 캐시 이름을 올려(현재 v9) 이전 버전이 남지 않게 했습니다. |

### 9-5. `index.html` 은 왜 최소화하지 않았나 (판단 기록)

`index.html` 은 **손으로 고치는 소스이자 그대로 배포되는 산출물**입니다(586KB, gzip 141KB: 인라인 `<style>` 70KB + 앱 스크립트 279KB).
최소화하려면 `dist/` 를 만들어 배포 경로를 바꿔야 하는데, 그 변경은 GitHub Pages 설정과 CI 배포 방식까지 함께 바꾸는 일이라 이번 범위를 넘습니다.

대신 **생성물은 최소화했습니다**: 정적 페이지의 공용 CSS 를 별도 파일로 굽고(§9-3) 주석·공백을 정리했으며, 홈도 프리렌더(§8-5)·스크립트 지연(§8-4)으로 첫 화면 비용을 줄였습니다.
어휘 데이터 34개 파일을 1개로 묶는 것도 검토했지만, 저장소에 원본 292KB 가 그대로 남은 채 묶음 파일이 하나 더 생기고 줄어드는 것은 요청 수뿐이라(HTTP/2 에서 왕복 비용이 작음) 하지 않았습니다.

| **조치** | 열 때 `history.pushState` 로 **항목 하나를 빌려** 두고, `popstate`(뒤로가기)가 오면 메뉴·안내 창을 닫습니다. 주소는 그대로라 화면은 바뀌지 않습니다. 직접 닫을 때(✕·Esc·바깥 누름·항목 선택)는 빌린 항목을 스스로 되돌려놓아, 뒤로가기 기록이 쌓이지 않습니다. 중첩(메뉴 → 안내 창)은 **개수(`guardDepth`)** 로 세어, 창이 남아 있으면 빌린 항목을 놓지 않습니다. |
| **범위** | 모바일 `☰` 메뉴, 데스크톱 `⋯ 더 보기`, `📘 TOEIC 시험 안내`, `❔ 목소리 도움말` — 네 곳 모두 같은 규칙입니다. |
| **보강** | 열면 첫 항목으로 초점 이동, 닫으면 `☰` 버튼으로 초점 복귀(항목을 골라 닫힐 때는 그대로 둠 — 시선이 이동한 화면으로 가야 하므로), Esc 로 닫기, 화면이 1024px 이상으로 넓어지면 자동 닫기. |
| **검증** | `tools/test-home-ux.mjs` §6 이 가짜 브라우저에서 열기→뒤로가기→Esc→항목 선택→화면 넓어짐을 모두 실행해 확인합니다. `check-browser.mjs` 는 실제 Chrome 에서 `history.back()` 뒤에도 주소가 그대로이고 패널·창만 닫히는지, **메뉴 → 안내 창으로 이어진 뒤에도 뒤로가기 한 번이면 창만 닫히는지** 봅니다. |

### 14-2. 교재 pager 의 단계명 중복 ✅

교재 데이터는 `level: "중급"` + `title: "중급 영문법"` 처럼 **단계명이 이미 제목 안에** 들어 있는데,
`tools/build-pages.mjs` pager 가 `${level} ${title}` 로 이어 붙여 `중급 중급 영문법`·`고급 고급 영어회화` 가 나왔습니다(6페이지 8곳).
제목만 쓰도록 고쳤고, 교재 허브 JSON-LD 의 `name` 에도 같은 중복이 있어 함께 정리했습니다.

### 14-3. 교재 과 단위 이동 ✅

한 페이지에 12과가 이어지고 페이지가 77KB까지 커져, 과를 읽다가 위 목차로 돌아가는 수고가 컸습니다(과 이동 링크 **0개**).

- **과 끝 이동 링크**(`.chnav`): `↑ 목차`(새 `#toc` 앵커) + `다음 과 →`. 자바스크립트가 없어도 동작하는 기본 수단이고,
  회화·문법 6권 **72개 과** 전부에 붙습니다.
- **현재 과 바**(`#chBar`): 목차를 지나 과로 들어가면 화면 아래에 현재 과(`07과 조동사 기초`)와 `🗂 목차` · `다음 과` 가 따라붙습니다.
  페이지 끝 pager 가 보이면 겹치지 않게 내려갑니다. 인쇄에서는 숨기고, 자바스크립트가 없으면 나타나지 않습니다(링크가 그 역할을 대신).

### 14-4. 가이드 이전/다음 편 이동 ✅

가이드 9편은 순서대로 읽는 코스인데 pager 에 `📕 가이드 전체 보기` 밖에 없었습니다. 유닛·교재와 같은 형태로 이전/다음 편을 넣었고,
제목이 모두 `TOEIC ` 로 시작해서 pager 에서는 접두어를 떼어 짧게 보여 줍니다(`← 접속사·전치사·접속부사 구분법`).

### 14-5. 홈 「이어서 학습」 ✅

1,000단어를 유닛 순서대로 외우는 사이트인데, 다시 왔을 때 “어디서 이어서 하지”를 알 길이 없었습니다.

- 마지막으로 본 카드를 `toeic1000_lastword` 에 기록하고(`showFlashCard`), 히어로의 `▶ 이어서 학습 n/1,000` 버튼이 **아직 안 외운 단어 중 그 단어부터** 시작합니다.
- 학습 기록이 없는 첫 방문에는 버튼을 숨깁니다(할 일이 겹침). 모두 외운 상태라면 오늘의 복습으로 안내합니다.
- 순서 계산은 `resumeOrder()` 라는 순수 함수로 분리해 회귀 테스트가 직접 검증합니다(`tools/test-home-ux.mjs` **5건**).

### 14-6. 교재 낱개 과 주소 ✅

책 페이지 하나가 12과 · 77KB 인 한 문서라 **“이 과”를 가리키는 주소가 없었습니다**(`grammar/basic.html#ch-07` 은 앵커일 뿐 검색·공유에 쓰기 어렵습니다).

- 과마다 `grammar/basic-01.html` · `conversation/conversation-basic-01.html` 처럼 **평범한 정적 페이지**를 만듭니다(문법 36 + 회화 36 = **72개**).
- 낱개 과 페이지는 `← 책 이름 전체` · `← 이전 과` · `다음 과 →` 로 이어지고, breadcrumb 은 4단계(홈 › 교재 › 책 › 과)입니다. `canonical` 은 각자 자기 주소를 가집니다.
- 책 페이지는 그대로 두고(연속 읽기 흐름 보존), 책마다 「🔗 과 하나씩 따로 보기」 목록으로 12개 과 주소를 안내합니다. 사이트맵에도 함께 들어갑니다.
- 하위 폴더(`basic/01.html`) 대신 같은 폴더의 평범한 파일로 둔 이유: 링크가 단순해지고, 생성물 검증(`tools/verify-generated.mjs`)이 디렉터리 한 단계만 훑어도 걸립니다.

> 내용이 책 페이지와 같은 본문을 담습니다(정본은 책 페이지). 검색 유입·공유를 위한 선택이고, 두 페이지가 서로를 링크합니다.

### 14-7. 홈 묶음 펼침 상태 기억 ✅

53개 섹션을 4묶음으로 접어 두었지만, **펼쳐 둔 상태가 저장되지 않아** 화면을 옮겼다 돌아오면 기본값(어휘 묶음만 펼침)으로 돌아갔습니다.

- 묶음 토글을 `toeic1000_homegroups` 에 저장하고, 홈에 들어올 때 복원합니다.
- 저장에 없는 묶음은 **HTML 기본값을 따릅니다**(나중에 묶음을 추가해도 그대로 펼침/접힘을 정할 수 있게).
- 인쇄용 임시 펼침은 저장하지 않습니다(인쇄하면 전부 펼쳐지는데, 그 상태가 저장되면 다음 방문부터 다 펼쳐집니다).
- 순수 로직은 `tools/test-home-ux.mjs` **5건**이 검증합니다(복원 · 기본값 유지 · false 반영 · 저장 · 깨진 JSON).

### 14-8. 교재 → 앱 딥링크 ✅

낱개 과 페이지는 “이 과”를 알려 주는 주소인데, 앱에서는 **단계만 지정할 수 있고 과는 다시 골라야** 했습니다.

- 낱개 과 페이지에 `✏️ 앱에서 이 과 문제 풀기` → `../index.html?level=basic&ch=5#grammar-quiz` (문법 교재만 — 회화는 앱에 문제 풀이가 없습니다).
- 앱은 `?level=` + `&ch=` 을 읽어 그 과의 연습 문제만 뽑고, 바로 문제를 시작합니다(기존 `?level=` 동작은 그대로).
- 필터가 걸린 사실을 화면에 드러냅니다 — `📖 기초 영문법 5과만 풀고 있어요` + `✕ 과 선택 해제`. (안 보이면 “왜 문제가 3개뿐이지”로 보입니다.)
- 없는 과 번호(`ch=99`)나 다른 단계의 과는 조용히 전체 과로 풀립니다(바깥에서 온 링크·오타 대비). 단계를 직접 바꾸면 필터도 풀립니다.
- 계산은 `parseDeepLink()`·`resolveChapter()` 두 순수 함수로 분리해 테스트 **8건**이 검증합니다.

### 14-9. 색인·메타 감사 강화 ✅

과 단위 페이지 72개가 늘면서 **주소가 어긋나는 사고**를 자동으로 잡아야 했습니다. 기존 감사는 “canonical 이 우리 사이트인가”까지만 봤습니다.

- `canonical` 이 그 페이지의 **배포 주소와 정확히 같은지** 확인합니다(폴더 index 는 폴더 주소).
- `<title>`·`canonical` 이 **다른 페이지와 겹치는지** 확인합니다(검색엔진이 어느 쪽을 색인할지 혼동).
- 낱개 과 페이지는 구조화 데이터에 `position`(몇 번째 과)과 `isPartOf`(어느 책)가 있어야 통과하고, 책으로 돌아가는 링크(`← 책 전체`)도 검사합니다.
- 실제로 `canonical` 을 책 페이지로 돌리고 `<title>` 을 복사해 두 가지가 모두 잡히는지 확인했습니다(검증 후 복구).

### 14-10. 점검 중 함께 드러난 것

- 문법 교재 허브 JSON-LD 의 `name` 이 `중급 중급 영문법` 이었습니다(사용자에게는 안 보이지만 검색엔진이 읽는 값).
- `tools/check-browser.mjs` 의 “회화 교재 카드 4장” 검사가 **고정 대기**에 기대고 있었습니다 — 확장 홈은 `requestIdleCallback` + `data/extra.js`(167KB) 뒤에 그려져
  브라우저가 바쁘면 0장으로 실패했습니다. 실제로 그려질 때까지 기다리도록 바꿔 재현성을 확보했습니다.
- 새 내비게이션을 **실제 브라우저에서 검증하는 검사 18건**을 `tools/check-browser.mjs` 에 추가했습니다(과 12개 인식 · 앵커 유효 · 바 표시/숨김 · 넘침 0px · 스크립트 오류 0건 · 낱개 과 페이지 4건 · 홈 묶음 유지 등).
- 정적 페이지가 55개 → **127개**(낱개 과 72개 추가)로 늘면서 `docs/*.md` 의 `audit:counts` 수도 함께 갱신했습니다. `npm run audit:site` 가 문서 수치를 실제 값과 대조합니다.

### 15-4. 정적 페이지 「맨 위로」 ✅

홈 앱에는 부동 `↑` 버튼이 있었지만 정적 페이지에는 없었습니다(유닛 페이지는 단어 33개가 이어져 길고, 교재 책 페이지는 77KB입니다).

- 인쇄에서는 숨깁니다(이미 `.pager`·`.chnav` 와 함께 인쇄 제외 목록에 넣었습니다).

### 15-5. 홈 깊은 구간 이동 ✅

§13-6 에 “섹션 메뉴가 스크롤과 함께 사라지므로 깊은 구간에서는 맨 위로를 거쳐야 함”이 남아 있었고, 목차 비고정은 의도된 선택이었습니다(스크롤 부담).
그래서 **고정하는 대신 한 섹션씩 옮기는 수단**을 붙였습니다.

- `▲ 이전 섹션` · `▼ 다음 섹션` — 700px 이상 스크롤하면 `맨 위로` 버튼 위에 나타납니다(모호한 화살표 대신 `aria-label`·`title` 로 뜻을 적었습니다).
- 이동은 기존 `scrollToEl()` 을 그대로 쓰므로 **접힌 묶음을 먼저 펼치고** `prefers-reduced-motion` 도 존중합니다. 현재 위치는 기존 `지금: …` 표시가 자동 갱신됩니다.
- `「/」` 단축키 — 검색창은 「단어 목록」 화면에만 있으므로(`showView` 가 다른 화면에서는 숨깁니다), 다른 화면이면 **목록 화면으로 옮긴 뒤 초점**을 줍니다. 입력 중(검색창·메모 등)에는 가로채지 않습니다.

### 15-7. sw.js 프리캐시 감사 ✅

프리캐시 목록은 손으로 관리하는데, 이를 검사하는 도구가 없었습니다. 실제로 **어긋나 있었습니다** — `data/conversation-*.js` 3개(홈이 첫 화면에서 내려받는 파일)와

- `tools/audit-site.mjs` 에 **5-1. sw.js 프리캐시 정합성**을 추가했습니다. `sw.js` 를 `vm` 으로 실제 실행해 목록을 읽고
  ① 없는 파일이 적혀 있는지 ② 홈이 내려받는 파일이 모두 들어 있는지 ③ 사이트맵의 섹션 허브가 들어 있는지 를 봅니다.
- 목록을 보강하고 `CACHE_NAME` 을 `v10` 으로 올렸습니다. 감사가 **실제로 잡는지** 확인했습니다 — 회화 3개를 일부러 빼니
  `sw.js: index.html 이 내려받는 파일이 프리캐시에 없습니다 — data/conversation-basic.js, …` 로 실패했습니다(검증 후 복구).

### 15-8. 정적 페이지 방문 분석 ✅

분석 스크립트(Umami)는 `index.html` · `privacy.html` · `terms.html` 3개에만 있었습니다. 검색 유입은 대부분 정적 페이지로 들어오는데 그 성과가 측정되지 않았습니다.
`build-pages.mjs` 템플릿에 넣어 **124개 페이지가 한 번에** 갖게 했습니다(공개 범위는 `privacy.html` 안내와 같습니다 — 쿠키 미사용 · 익명 통계).

### 15-9. 점검 중 함께 드러난 것

- **`tools/check-browser.mjs` 가 아예 중단되고 있었습니다.** `evaluate()` 로 넘기는 템플릿 리터럴 안의 `split("\n")` 이 실제 줄바꿈으로 치환돼,
  브라우저가 `SyntaxError` 로 실패했습니다(CI 는 이 도구를 돌리지 않아 통과해 왔습니다). `split("\\n")` 으로 고쳤고, 이번 §15-2~15-5 검증이 그대로 돌아갑니다.
- **`.gitignore` 의 `*.pyc` 패턴이 깨져 있었습니다** — 앞 줄과 붙어 `*.pyc# 생성된 쇼츠 영상 (…)` 한 줄이 되어 주석까지 삼켜졌습니다(`__pycache__/` 덕에 티가 나지 않았습니다).
- `tools/serve.mjs` 가 **커밋되지 않은 채** `package.json` 의 `serve` 스크립트만 이를 가리키고 있었습니다 — 새로 받으면 `npm run serve` 가 실패합니다. 추적 대상에 넣고,
  헤더 주석의 “tools/ 는 서빙 대상 경로가 아님” 도 실측에 맞게 고쳤습니다(로컬 서버·Pages 모두 루트를 서빙합니다).
- `promo/README.md` 오타(`뜽니다` → `뜹니다`) — `audit:text` 는 사이트 콘텐츠(17,008개 문자열)를 보므로 `promo/` 는 사각지대입니다.
- `engines`(>=18) · CI 매트릭스(18.x/20.x) vs 실제 도구 요구(전역 `WebSocket` → Node 22+): `>=22` 와 `22.x`/`24.x` 로 맞췄습니다.
