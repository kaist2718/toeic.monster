## 1. P1 — 사용 흐름을 막는 문제 (모두 수정)

### 1-1. 문법 교재·문법 문제 풀이가 홈 42·43번째 섹션에 있었음 ✅

| | |
| --- | --- |
| **증상** | 홈은 `home-section` **52개**를 한 페이지에 쌓는 구조입니다. 새 문법 콘텐츠가 42·43번째에 있어, 칩을 47번째까지 옆으로 스크롤하거나 페이지를 40섹션 이상 내려야 닿을 수 있었습니다. |
| **조치** | `📐 오늘의 문법 팁`(4번째 섹션) 바로 뒤(5·6번째)로 이동. 문법 학습 동선이 **팁 → 교재 → 문제**로 이어집니다. |
| **검증** | 섹션 순서 계측: `… 4 오늘의 문법 팁 / 5 문법 교재 3단계 / 6 문법 문제 풀이 / 7 학습 모드` |

### 1-2. 정적 페이지에 다크 모드가 없음 ✅

| | |
| --- | --- |
| **증상** | 앱은 `toeic1000_theme` 으로 다크 테마를 지원했지만, 정적 페이지 47개는 흰 화면 고정이었습니다. |
| **조치** | ① 첫 페인트 전 `<html class="dark-pending">` 적용 인라인 스크립트 ② `:root` 변수를 `html.dark-pending` 에서 어둡게 재정의(배경·카드·본문·경고/정답 배경 등 19개 토큰) ③ 하드코딩 색을 변수로 치환. |
| **검증** | 생성 페이지 계측: `dark-pending` 2건(`units/unit-01.html`·`grammar/basic.html` 등 전 페이지 공통). 앱에서 고른 테마가 정적 페이지로 그대로 이어집니다. |

### 1-3. 긴 홈에서 위로 돌아갈 길이 없음 ✅

| | |
| --- | --- |
| **증상** | 홈이 52섹션(약 4만 px)인데 섹션 메뉴는 스크롤과 함께 사라지고(비고정), `맨 위로` 버튼도 없었습니다. 30번째 섹션쯤에서 목차로 돌아가려면 손가락으로 3만 px 를 되감아야 했습니다. |
| **조치** | 우하단 부동 `↑ 맨 위로` 버튼(`#toTop`) 추가. 700px 이상 스크롤하면 나타나고, `prefers-reduced-motion` 이면 애니메이션 없이 즉시 이동합니다. 인쇄 시 숨김. |
| **검증** | 마크업·스크롤 임계값(700px)·`reduce-motion` 분기 계측 확인. |

## 2. P2 — 불편·일관성 문제 (모두 수정)

### 2-1. 홈 한 페이지에 52개 섹션을 한 줄 칩 49개로 탐색 ✅

- **증상**: `.section-nav` 가 `overflow-x: auto` 라, 가로 스크롤이 있다는 단서 없이 49개 칩을 옆으로 밀어야 했습니다. 데스크톱(마우스)에서는 뒤쪽 칩 접근이 특히 어려웠습니다.
- **조치**: ① 자주 쓰는 8개만 위 줄에 노출 ② 나머지 44개는 `🗂 전체 목차` 버튼으로 **주제별 4묶음**(어휘 익히기 / 파트별 훈련 / 말하기·쓰기 / 실전·학습 관리)에 담아 접기 ③ 넓은 화면(≥900px)은 펼친 상태로 시작 ④ `aria-expanded`·`aria-controls` 로 접힘 상태 노출.
- **검증**: 섹션 52 = 칩 52(모두 연결) · 그룹 4개 · 토글 동작 · `npm run audit` 의 "섹션 메뉴 칩 52개(모두 연결됨)".

### 2-2. 정적 페이지에서 앱 학습으로 돌아오는 길이 없음 ✅

- **증상**: 교재 페이지 CTA 가 `홈` 하나뿐이고 앱은 해시를 해석하지 않아, "이 교재의 문제를 앱에서 풀기" 로 바로 연결할 수 없었습니다.
- **조치**: ① 앱에 해시 진입 지원(`goToHash` — `#grammar-quiz`·`#grammar-quiz-basic` … `#units`·`#dashboard` 등) ② `?level=basic#grammar-quiz` 형태로 **단계까지 지정해 바로 시작** ③ 교재 상단에 `✏️ 이 교재 문제 풀기` 버튼 배치.
- **검증**: 교재 → 앱 링크 계측(`../index.html?level=basic#grammar-quiz`), `applyLevelQuery()` + `hashchange` 리스너 확인.

### 2-3. 같은 화면에 이름이 비슷한 문법 진입점 3개 ✅

- **증상**: `📘 문법 가이드`(자료 허브의 탭) · `📘 문법 교재`(칩) · `✏️ 문법 문제`(칩)가 한 화면에 공존해 무엇이 다른지 구분되지 않았습니다.
- **조치**: 첫 번째를 목적지 이름인 **`📐 필수 문법 보기`** 로 변경.

### 2-4. 모바일 터치 영역이 44px 미만인 컨트롤 ✅

- **증상**: `.btn` 이 모바일에서 약 33px, `quiz-head select` 가 38px 이었습니다.
- **조치**: `select` → `min-height: 44px`, 모바일 `.btn` → `min-height: 40px`(프로젝트가 쓰던 "약 40px" 기준에 맞춤).
- **검증**: `@media (max-width: 640px)` 규칙 계측.

### 2-5. 문법 표가 좁은 화면에서 빽빽함 ✅

- **증상**: `.gtable` 3열이 375px 화면에서 한 열 약 100px 로 좁아 읽기 어려웠습니다.
- **조치**: 표를 `.gtable-wrap`(`overflow-x: auto`) 로 감싸고 `min-width: 340px` 를 주어, 좁은 화면에서는 표만 가로로 밀리게 했습니다. 520px 이하에서는 글자·여백을 한 단계 줄였습니다.

### 2-6. 많은 조작 요소에 키보드 초점 표시가 없음 ✅

- **증상**: `:focus-visible` 규칙이 `.btn`·`.lvl-btn`·`.quiz-opt` 등 6종에만 걸려 있어, **섹션 칩·토글·오답 보기(`.bank-opt`)·모드 버튼(`.mode-btn`)·유닛 버튼** 등은 키보드로 이동해도 어디에 초점이 있는지 보이지 않았습니다.
- **조치**: `a` · `button` · `summary` · `select` · `input` · `[tabindex]` 전역 `:focus-visible` 윤곽선(3px `--accent`)으로 통일.
- **검증**: 계측 — 접근 가능한 이름이 없는 버튼 0개, 라벨 없는 `select`/`input` 0개, 중복 `id` 0개.

### 2-7. 상단 칩 순서가 문서 순서와 어긋남 ✅

- **증상**: 첫 줄 칩이 `… 문법 문제(6번째 섹션) → 오늘의 대화문(23번째) → 학습 모드(7번째)` 순이어서, 대화문으로 갔다가 다시 위로 되돌아와야 했습니다.
- **조치**: `학습 모드 → 오늘의 대화문` 순으로 교체해 첫 줄이 `1·2·3·4·5·6·7·23` 로 단조 증가하게 했습니다.

## 5. 잘 되어 있는 점 (유지)

- 문항 카드·보기·피드백이 모두 `<button>` 기반이라 키보드만으로 풀이가 가능합니다.
- 영어 단어·발음기호·예문에 `lang="en"` 이 적용되어 화면 낭독기가 영어로 읽습니다(앱 렌더러 + 정적 페이지 공통).
- 정적 페이지의 🔊 버튼은 앱의 TTS 설정(`toeic1000_ttsvoice`·`ttslang`·`ttsrate`)을 공유해 목소리·속도 선택이 페이지를 넘어 이어집니다.
- 미지원 브라우저에서는 🔊 버튼을 숨기고(`hidden`), Esc 로 낭독을 멈출 수 있습니다.
- 새 문법 섹션은 정적 링크(`바로가기`)를 함께 노출해 JS 를 실행하지 않는 크롤러(네이버 Yeti)도 교재 3권을 발견할 수 있습니다.
- 오답노트를 포함한 모든 학습 기록은 localStorage 에만 저장되고 서버로 전송되지 않습니다.
