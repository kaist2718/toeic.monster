# 빈도순 기출 어휘 200선 — 예문·IPA 보강 및 쇼츠 연동 설계

> 목적: `data/extra.js` 의 **frequency(빈도순 기출 어휘 200선)** 를 기존 단어 카드(`data/unitNN.js`)와
> **같은 밀도**(IPA · 한글 발음 · 예문 · 해석)로 보강하고, 그 데이터로 `promo/` 숏폼을 만들 수 있게 한다.
> 전제: 정적 사이트 · 서버 없음 · `extra.js` 는 브라우저와 `tools/build-pages.mjs`(vm) 가 함께 읽음.

---

## 1. 지금 격차

| 항목 | 단어 카드 (`unitNN.js`) | 빈도 어휘 (`extra.frequency`) |
| --- | --- | --- |
| 행 형식 | `[단어, IPA, 한글발음, 뜻, 예문, 해석, 예문한글발음]` (7필드) | `[단어, 뜻, 품사]` (3필드) |
| IPA | 있음 | **없음** |
| 한글 발음 | 있음 | **없음** |
| 예문·해석 | 있음 | **없음** |
| 쇼츠 렌더러 | `render_slide()` | **미지원** (숙어도 별도 함수) |

즉 지금 빈도 어휘로 쇼츠를 만들면 카드에 **단어·뜻·품사만** 들어가 시각 밀도가 크게 떨어진다.

### 1-1. 보강 전 재사용 가능량 (실측)

| 구분 | 개수 | 근거 |
| --- | --- | --- |
| 전체 | 200 | `extra.frequency` |
| UNIT 표제어와 **철자 일치** → 예문·IPA·한글발음·해석 그대로 재사용 | **67** | `unit*.js` 1,000단어와 대조 |
| paraphrase 문장에 등장 | 109 | 문장은 있으나 표제어 전용 예문·해석으로 쓰기엔 부적합 |
| UNIT 예문 없음 → **신규 예문 작성 필요** | **133** | 위 67을 제외한 나머지 |
| 다어절 표제어 | 2 | `available upon request`, `adhere to` |

→ **IPA·예문 확보의 약 1/3(67개)은 기존 데이터를 그대로 옮겨 해결**되고, 나머지 133개만 새로 채우면 된다.

> **주의(실제 적용 결과)**: 위 67개 중 **4개는 UNIT 예문의 뜻/품사가 빈도 목록과 달라 재사용에서 제외**했다 —
> `resume`(재개하다 ↔ 이력서), `deposit`(보증금 ↔ 예금하다), `monitor`(모니터링하다 ↔ 모니터),
> `withdraw`(철회하다 ↔ 인출하다). 이들은 3필드로 남겨 §4-2 에서 채운다. 따라서 실제 재사용은 **63개**,
> 신규 작성 대상은 **137개**다. 제외 목록은 `tools/enrich-frequency-reuse.py` 의 `SKIP_SENSE_MISMATCH` 에 있다.

## 2. 데이터 설계

### 2-1. 배치 — `extra.frequency` 행에 **필드를 덧붙인다** (in-place append)

```js
// 기존:  [단어, 뜻, 품사]
// 이후:  [단어, 뜻, 품사, IPA, 한글발음, 예문, 해석, 예문한글발음]
["available", "이용 가능한", "형용사", "/əˈveɪləbl/", "어-베일-러-블",
 "Tickets are available at the front desk.", "티켓은 안내 데스크에서 구할 수 있다.",
 "티-킷츠 아 어-베일-러-블 앳 더 프런트 데스크"],
```

**앞 3필드(단어·뜻·품사)의 자리는 그대로 둔다.** 이유는 아래 소비처가 전부 인덱스 0~2만 읽기 때문이다 —
행을 길게 만들어도 **호환성 손실이 0**이다.

| 소비처 | 읽는 인덱스 |
| --- | --- |
| `assets/app.js` `renderFrequency()` | `w[0]`, `w[1]`, `w[2]` |
| `tools/build-pages.mjs` `buildFrequencyPage()` | `w[0]`, `w[2]`, `w[1]` |
| `tools/audit-text.mjs` | `w[0]` |
| `tools/audit-site.mjs` | 개수만 |
| `tools/make_workbook.py` `parse_extra()` | `cols[0..2]` |

> **대안(기각)**: 단어 카드와 **같은 순서**(IPA를 1번으로)로 재배열하거나, 별도 `data/frequency.js` 를 신설하는 방식.
> 전자는 위 소비처 5곳을 모두 고쳐야 하고, 후자는 단어·뜻이 두 곳에 복제되어 드리프트가 생긴다.
> **단일 소스(extra.js) 유지 + 후방 호환**이 이 저장소의 감사 철학에 맞는다.

### 2-2. 필드 순서 차이는 promo에서 어댑터 한 줄로 흡수

빈도 행 순서(뜻·품사가 앞)는 단어 카드 순서(IPA가 앞)와 다르다. 쇼츠 렌더러는 단어 카드 순서를 기대하므로,
`promo` 가 행을 **단어 카드 순서 튜플**로 한 번 변환한다.

```
빈도 행  [단어, 뜻, 품사, IPA, 한글발음, 예문, 해석, 예문한글발음]
        ↓ 어댑터
카드 튜플 [단어, IPA, 한글발음, 뜻, 예문, 해석, 예문한글발음]
```

## 3. IPA·한글 발음 확보 전략

### 3-1. IPA

| 구간 | 방법 |
| --- | --- |
| UNIT 일치 67개 | `unit*.js` 의 IPA를 **그대로 복사** (사이트 표기와 100% 일치) |
| 나머지 131개 단일어 | **CMUdict(ARPAbet) → IPA** 변환으로 생성. 1회성 스크립트로 산출물을 커밋 |
| 다어절 2개 | 각 단어 IPA를 이어 붙이되, 표제어가 구(句)임을 표기(`available upon request` 등) |

- 생성 스크립트는 `tools/make-frequency-ipa.py` (Python, fontTools 를 쓰는 `make-font-subset.py` 와 같은 성격의 **1회성 도구**) 로 두고, **결과만 `extra.js` 에 커밋**한다. 런타임 의존성 0 유지.
- 표기 규칙은 **단어 카드와 동일**하게 맞춘다(예: `/ˈkʌmpəni/` 형태, 강세 표기 포함). 사이트 안에서 두 표기가 섞이면 안 된다.
- 스크립트는 결정적이어야 한다(CMUdict 버전 고정). 검수는 무작위 20개 표본 육안 확인 + 기존 67개와의 일관성 비교.

### 3-2. 한글 발음

- UNIT 일치 67개는 재사용. 나머지는 **예문 작성 시 함께 채우는 것을 권장**하되, 렌더러가 빈 값을 허용하므로 **후순위로 미뤄도 카드가 깨지지 않는다**(`render_slide` 는 `kor_pron` 이 있으면 줄을 그리고 없으면 넘어감).
- 무리한 자동 생성은 기존 수기 표기(`컴-퍼-니` 식 음절 하이픈)와 어긋나므로 **자동화하지 않는다.**

## 4. 예문·해석 확보 전략

### 4-1. 1차 — 재사용 매핑

1. UNIT 표제어 일치 67개 → 해당 UNIT 예문·해석·예문한글발음 **그대로 복사.**
2. 나머지 133개 → `paraphrase`(200)·`dictation`(24)·`situations`·`part1`·`part6/7` 문장을 훑어 **표제어를 포함하고 TOEIC 맥락인 짧은 문장**이 있으면 후보로 뽑는다(자동 후보 리포트 → 사람이 채택).

### 4-2. 2차 — 신규 작성 (약 137개 = 133 + 의미 불일치 4)

작성 기준(기존 카드·밀도 감사와 동일):

| 기준 | 값 | 이유 |
| --- | --- | --- |
| 예문 길이 | **6단어 이상**, 카드에 최대 5줄 | `audit:density` 가 5단어 이하 예문을 0% 로 요구 |
| 표제어 포함 | 필수 | 카드가 표제어를 설명하는 자료 |
| 문맥 | 비즈니스·TOEIC (사무·회의·계약·고객 등) | 사이트 톤과 통일 |
| 해석 | 자연스러운 한국어, 예문과 1:1 | 카드 하단 표시 |
| 예문한글발음 | 작성 시 함께(후순위 허용) | 카드 밀도(선택) |

> 같은 표제어가 UNIT·paraphrase에도 있으면 **예문이 중복될 수 있다.** 이는 의도된 재사용이나,
> 빈도 카드만의 색을 원하면 신규 작성 구간(133개)에서 다른 예문을 쓴다.

## 5. promo 파이프라인 변경

숙어(`--idioms`)를 추가했던 것과 **같은 패턴**으로 `--frequency` 를 더한다.

### 5-1. `publish.py`

| 추가 | 내용 |
| --- | --- |
| `load_frequency()` | `extra.js` 의 `frequency: [` 블록을 중괄호 매칭으로 떼어 파싱(`make_workbook.extract_block` 과 동일 방식), 행을 **단어 카드 순서 튜플**로 정규화 |
| `FREQUENCY_BUCKET = "frequency"` | `posted.json` 의 `words` 키. `IDIOM_BUCKET` 과 같은 자리 |
| `build_meta()` 분기 | 사이드카가 없을 때 `--frequency` 면 남은 항목에서 골라 제목·설명 생성. 제목 `"available | TOEIC 빈출 어휘 | toeic.monster"` |
| 메뉴·CLI | `--frequency`, 메뉴 22(빈도 쇼츠 생성)·23(생성 후 게시) |

### 5-2. `make_shorts.py`

| 추가 | 내용 |
| --- | --- |
| `--frequency` | `load_frequency()` 로 200개 로드 → 카드 순서 아이템 구성 |
| `render_freq_slide()` | `render_slide()` 를 복제하되 상단 칩만 **"TOEIC 빈출 어휘" + 순번 뱃지**로 교체 |
| 출력 파일명 | `frequency_<표제어slug>_shorts.mp4` (순번 기반, 배치끼리 덮어쓰기 방지) |

> `render_idiom_slide()` 처럼 함수를 나눠 단어 카드를 건드리지 않는다 —
> 매일 도는 단어·숙어 영상이 빈도 작업으로 깨지지 않게 하는 기존 방침을 따른다.

## 7. 단계별 실행 계획

| 단계 | 작업 | 산출물 | 예상 |
| --- | --- | --- | --- |
| 0 | (완료) 재사용 가능량 측정 — 67 재사용 / 133 신규 | §1-1 | 0.5일 |
| 1 | **재사용분 63개 반영 완료**(`tools/enrich-frequency-reuse.py`) · IPA 생성은 예문과 함께 | `extra.js` 일부 8필드 | 0.5일 |
| 2 | ✅ 완료 — `tools/frequency-coverage.mjs` (재사용 후보 **89/137 = 65%**) | 커버리지 리포트 | 0.5일 |
| 3 | ✅ 완료 — `tools/frequency-content.json` 137개 작성 → `extra.js` **전부 8필드(200/200)** | 콘텐츠 | 2~3일 |
| 4 | ✅ 완료 — `audit-content` all-or-nothing·예문 검증, `audit-text` 필드 검사 | 감사 통과 | 0.5일 |
| 5 | ✅ 완료 — promo `--frequency` (publish·make_shorts·메뉴 22/23·README) | 생성·게시 동작 | 0.5~1일 |
| 6 | ✅ 완료 — 빈도 페이지(`units/frequency.html`)에 발음기호·한글 발음·예문·해석 노출 | 사이트 반영 | 0.5일 |
| 7 | ✅ 완료 — 다음 포맷: 동의어 치환 **퀴즈 숏폼**(`--paraphrase`, 메뉴 24/25) | 퀴즈 200문제 | 1일 |

> **진행 상황(1~7단계 완료)**: 빈도 200선이 전부 8필드가 되었고, `npm run check` 로 감사·테스트를
> 통과했습니다. promo 는 `make_shorts.py --frequency` 와 `publish.py --frequency` (메뉴 22·23)로
> 생성·게시가 모두 동작합니다(사이드카 `kind: "frequency"`).
>
> 이어서 **6단계(사이트 노출)** 와 **7단계(퀴즈 포맷)** 까지 마쳤습니다.
>
> - **6단계**: `tools/build-pages.mjs` 의 `freqItem()` 이 8필드 행이면 유닛 카드와 같은 밀도로
>   그립니다(발음기호·한글 발음·품사 칩·뜻·예문·예문 한글 발음·해석). 보강 전 3필드 행도 예전처럼
>   그릴 수 있어 데이터가 되돌아가도 페이지가 깨지지 않습니다.
> - **7단계**: `make_shorts.py --paraphrase` 가 한 문제를 **문제 슬라이드 → 정답 슬라이드** 두 장으로
>   만듭니다(보기 A~D, 표적 표현 강조 + 밑줄, 정답·해설). `publish.py --paraphrase` 와 메뉴 24·25,
>   사이드카 `kind: "paraphrase"`(보기·발문 포함)로 제목·설명까지 자동 생성됩니다.
> - **남은 콘텐츠 표시**: 생성·게시가 끝날 때(그리고 `--dry-run` 종료 시) 종류별 사용/전체/남음 표를
>   출력합니다. `publish.py --list-remaining`(메뉴 26)으로 수량만 볼 수도 있습니다.

**합계 약 5~7일**(1인). 1~3단계가 대부분 콘텐츠 작업이고, 코드는 4~5단계에 몰려 있다.

### 7-1. 검증 게이트

```bash
npm run audit:content   # 빈도 행 전부 보강됐는지(부분 보강 실패)
npm run audit:text      # 새 예문·해석 철자·TTS
npm run check           # 감사 4종 + 밀도 + 테스트 + 빌드
python promo/make_shorts.py --frequency --words 5 --dry-run
python promo/publish.py --video assets/shorts/frequency_available_shorts.mp4 --frequency --dry-run
python promo/make_shorts.py --paraphrase --words 3 --dry-run   # 퀴즈(7단계)
python promo/publish.py --list-remaining                        # 남은 콘텐츠 수량
```

## 8. 리스크와 완화

| 리스크 | 완화 |
| --- | --- |
| 부분 보강 상태로 커밋 → 카드가 어떤 건 3필드·어떤 건 8필드 | `audit-content` 가 **all-or-nothing** 으로 실패시킴 |
| 자동 IPA가 사이트 수기 표기와 어긋남 | 67개는 사이트 값 재사용, 나머지는 표기 규칙 동일화 + 표본 검수 |
| 예문이 기존 UNIT·paraphrase와 중복 | 재사용은 의도. 신규 구간(133)에서 변별 |
| `extra.js` 비대 → 첫 로딩 | 필드만 늘어 총량은 소폭. 예문을 **사이트 페이지에 노출하지 않으면**(쇼츠 전용) 홈/페이지 크기 영향 없음 |
| 사이트 페이지에 예문을 넣을지 | **결정: 넣었다**(6단계) — 밀도·SEO 이점을 택했습니다. `units/frequency.html` 이 166KB 로 커졌지만 정적 페이지라 첫 로딩에는 지연 로드(`extra.js`)로만 영향이 있고, 접근성·예산 감사는 통과합니다 |
| 퀴즈 슬라이드에 긴 문장·긴 보기가 넘침 | 렌더 함수가 글자 크기를 줄이며 맞추고, 200문항·400장을 전부 렌더해 안전 영역을 넘지 않는지 확인했습니다 |
